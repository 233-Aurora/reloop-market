# CampusEcho 数据库修改文档

本地开发库：`campusecho`  
结构变更一律通过 Flyway 迁移脚本管理，已执行的迁移文件不得修改。

## V7 — 站内消息扩展（通知）

- 迁移文件：`src/main/resources/db/migration/V7__extend_messages_for_notifications.sql`
- 应用时间：实现站内消息与交易/举报通知时
- 变更说明：
  - `messages` 新增 `report_id`（可空，关联 `reports`，删除举报时置空）
  - `messages` 新增 `item_id`（可空，关联 `items`，删除物品时置空）
  - 为 `message_type` 增加检查约束，限定当前系统通知类型
  - 新增 `report_id`、`item_id`、`trade_request_id` 索引，便于按业务实体查询通知
- 本地应用方式：启动后端或执行测试时由 Flyway 自动迁移
- 回滚建议：如需回滚，需新建迁移删除约束、索引与列；不要直接改写 `V7` 文件

### 当前支持的 message_type

| 类型 | 含义 |
| --- | --- |
| `TRADE_REQUEST_CREATED` | 买家发起交易请求，通知卖家 |
| `TRADE_REQUEST_ACCEPTED` | 卖家接受交易，通知买家 |
| `TRADE_REQUEST_REJECTED` | 卖家拒绝或系统自动拒绝，通知买家 |
| `TRADE_REQUEST_CANCELLED` | 买家取消待处理请求，通知卖家 |
| `TRADE_CONFIRMATION_RECEIVED` | 一方确认完成，通知另一方 |
| `TRADE_COMPLETED` | 双方确认后交易完成 |
| `TRADE_CANCELLED_BY_MODERATION` | 因屏蔽物品或停用账户取消未完成交易 |
| `REPORT_RESOLVED` | 举报处理完成，通知举报人 |
| `REPORT_REJECTED` | 举报被驳回，通知举报人 |
| `ITEM_BLOCKED` | 物品被管理员屏蔽，通知卖家 |
| `ITEM_RESTORED` | 物品解除屏蔽，通知卖家 |
| `ACCOUNT_SUSPENDED` | 账户被停用，通知被停用用户 |

## V8 — 交易争议与管理员仲裁

- 迁移文件：`src/main/resources/db/migration/V8__add_trade_disputes.sql`
- 应用时间：实现交易争议与管理员仲裁时
- 变更说明：
  - `trade_requests.status` 增加 `DISPUTED`
  - 新增 `trade_disputes` 表，记录发起人、被申请方、原因、状态、仲裁结果与处理信息
  - 同一交易最多一条 `OPEN` 争议（部分唯一索引）
  - `messages` 新增 `dispute_id`，并扩展争议相关 `message_type`
- 职责边界：
  - 争议：处理已接受交易的履约纠纷（完成/取消裁定）
  - 举报：处理内容违规与账户治理（屏蔽物品/停用用户）
- 本地应用方式：启动后端或执行测试时由 Flyway 自动迁移
- 回滚建议：如需回滚，需新建迁移删除表、列与约束；不要直接改写 `V8` 文件

### trade_disputes 关键字段

| 字段 | 说明 |
| --- | --- |
| `trade_request_id` | 关联交易 |
| `item_id` | 关联物品 |
| `opener_id` / `respondent_id` | 发起人与对方 |
| `reason` | `NON_DELIVERY` / `ITEM_NOT_AS_DESCRIBED` / `PAYMENT_ISSUE` / `NO_SHOW` / `OTHER` |
| `status` | `OPEN` / `RESOLVED` / `REJECTED` |
| `resolution` | `COMPLETE_TRADE` / `CANCEL_TRADE` / `NONE` |
